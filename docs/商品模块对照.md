## 2. 五条商品查询规则 → 实现对照

| # | 规则（幻灯片原文） | 实现 | 位置 |
| --- | --- | --- | --- |
| 1 | 游客可以浏览，本模块只读取数据，加入购物车留到购物车模块 | 商品/分类/详情路由都不在鉴权拦截名单内；`/cart/**`、`/orders/**` 等才要求登录 | `config/WebConfig`、`security/AuthInterceptor` |
| 2 | 只展示上架商品，列表排除 DRAFT；访问不存在或下架商品给出不可用提示 | 列表 SQL 固定 `status='ON_SALE'`；详情对非上架商品抛 `NotFoundException`，由全局处理器渲染 404 页并显示"商品不存在或已下架。" | `ProductMapper.xml`、`ProductService#detail`、`GlobalExceptionHandler` |
| 3 | 两级分类筛选：一级包含其下商品；二级入口默认选中对应类型，切换类型仍在所属一级范围内 | `search()` 命中二级分类时用 `typeOf()` 推出宠物/用品类型，再把 `categoryIds` 收敛到该一级分类下同类型的二级分类 | `ProductService#search`、`CategoryService#typeOf` |
| 4 | 同一商品标识：首页、列表、详情统一用数据库商品 ID 关联，SKU 只用于展示 | 所有链接形如 `/product?id=<真实ID>`、`/category?categoryId=<真实ID>`；模板里不再出现 `?sku=` | `Main.html`、`Category.html`、`Cart.html`、`ViewOrder.html` |
| 5 | 展示规则一致：零库存仍可展示；金额用人民币；推荐区按预定排序取上架商品 | 查询不过滤 `stock`；金额 `¥` + 两位小数 + 千分位；精选 `ORDER BY sort_order, id` | `ProductMapper.xml`、`MoneyFormatter` |

## 3. Main 页五个小任务 → 实现对照

| 任务 | 视频要求 | 实现 |
| --- | --- | --- |
| 01 实体、Mapper 与字段验证 | 映射 `Category`、`Product`，读真实记录核对字段 | `entity/Category`、`entity/Product`；`CategoryMapperIT`（5 例）、`ProductMapperIT`（4 例）连真实库核对字段映射 |
| 02 分类导航 Service 与测试 | 一次查询，内存里组织一级 + 二级，禁止按父类逐个查询 | `CategoryService#all()` 一次 `selectAllOrdered()`，`ProductService#home()` 在内存里分组；`CategoryServiceIT` 4 例 |
| 03 新品、精选分别查询与测试 | 新品最多 3 件（`created_at, id` 降序）；精选最多 4 件（`sort_order, id` 升序）；都只要上架商品 | `ProductMapper#selectHomeNew(3)`、`#selectHomeFeatured(4)`；`ProductServiceIT` 用 Mapper 全量读取在 Java 侧独立算期望值再比对 |
| 04 Controller 与 Thymeleaf | 传 Model、循环渲染、处理空列表与缺图 | `HomeController#main` 传 `home`；`Main.html` 用 `th:each`/`th:if` 渲染，空列表整段不渲染，图片 `onerror` 回退 `/images/logo.png` |
| 05 浏览器验收 | 核对数量、排序、图片、分类与商品链接 | 见 `docs/视觉验收.md` 与 `docs/screenshots/home.jpg` |

## 4. 视频里的具体约定 → 本工程

| 约定 | 视频原文/做法 | 本工程 |
| --- | --- | --- |
| 路由不带 `.html`、全小写 | `/main`、`/category`、`/product?id=` | 一致；`/`、`/index` 返回欢迎页 |
| 商品详情用 ID 不用 SKU | "替换原 `?sku=`" | 主路由 `/product?id=`，同时保留 `/product/{id}` 兼容旧链接 |
| 价格格式 | `¥` + 两位小数 + 千分位，`formatDecimal(...,'COMMA',...)` | `MoneyFormatter` 用 `Locale.ROOT` + `%,.2f`，输出 `¥3,800.00` |
| 分类入口展示一级 + 二级 | `<b>一级名</b><small>CODE</small><small class="category-sub">宠物 / 用品</small>` | 同构：`node.category().name` / `.code` / `#strings.listJoin(children.![name], ' / ')` |
| 不展示伪造内容 | 删除 NEW 静态角标、伪造 `<small>` 文案、卡片 `+` 加购、整个"本周热卖"区；"emoji 图标因 DB 无对应字段而移除" | 首页已无热卖区、无 NEW/热卖角标、无 `+`；分类条改为真实 `code` 与二级名称，删掉了硬编码 emoji 映射 |
| 缺图兜底 | `onerror="this.onerror=null;this.src='/images/logo.png'"` | 首图/小卡/推荐卡都加了同样的 `onerror`，服务端另有 `coverImage == null` 兜底 |
| MyBatis SQL 日志 | `mybatis-plus.configuration.log-impl=...Slf4jImpl` + `logging.level.org.csu.mypetstore.mapper=debug` | 写进 `application-dev.yaml` |
| 集成测试命名 | `*IT` + `@SpringBootTest` + `@ActiveProfiles("dev")` + `@Transactional` 只读回滚 | `CategoryMapperIT`、`ProductMapperIT`、`CategoryServiceIT`、`ProductServiceIT`，共 19 例 |
| 分层边界 | Controller 只"调 Service → 塞 Model → 返回视图名"，查询规则全在 Service | 一致：`HomeController` 只调用 `ProductService#home()` |

## 5. 已知差异（有意保留）

| 视频 | 本工程 | 原因 |
| --- | --- | --- |
| 只做 Main，明确"暂不实现 Category 筛选与 Product 详情" | 三个页面（含分类筛选、搜索、分页、详情相册）都已实现 | 实验一按 PRD 交付 P0 全部功能；视频是分阶段教学，Main 只是第一站 |
| 包结构 `controller / entity / mapper / service` | `web / entity / mapper / service / security / config` | `web` 更贴切地表示"Web 层"，且本工程多了鉴权与 CSRF 过滤器；不影响分层语义 |
| 登录路由 `/signon` | `/login` | 本工程登录还承担 `returnUrl` 回跳与 CSRF 校验 |
| 老师现场把 `pets/`、`supplies/` 素材拷进 `static/images` | 素材已随仓库提供，且 40 张封面由 `scripts/generate_product_art.py` 生成 | 避免"两栏全破图"，可直接复现 |

## 6. 复现验证

```powershell
# 只跑单元测试（不需要数据库）：43 个
mvn -B -f MyPetStore-SSM\pom.xml test

# 集成测试需要 3307 上的 MySQL 与演示数据：19 个
$env:DB_PORT="3307"
mvn -B -f MyPetStore-SSM\pom.xml test "-Dtest=CategoryMapperIT,ProductMapperIT,CategoryServiceIT,ProductServiceIT"
```

`*IT` 不在 Surefire 默认匹配范围内，所以 `mvn test` 不会因为缺少数据库而失败；
这也正是视频里"IT 依赖真实外部数据库"的约定。
