## 1. 视频中的工程结构

视频展示的是：

```text
MyPetStore-SSM/
├─ pom.xml
├─ src/main/java/
├─ src/main/resources/
├─ src/test/java/
└─ database/
```

本项目保留同样的可读结构，并补充管理端：

```text
MyPetStore-SSM/                # 用户端，含 src/main/resources/database/ 副本
MyPetStore-admin/              # 管理端，独立构建/运行
database/                      # 共享 SQL 唯一来源
docs/                          # 实验文档
scripts/                       # smoke 脚本
```

视频中的 `MyPetStore-SSM-demo` 是单人演示工程；本项目按 PRD 拆成用户端与管理端两个真实工程，端口、Cookie、会话独立。

## 3. 数据库配置对照

视频中：

1. 在 MySQL 中新建 `MyPetStore`；
2. 导入 `01-schema.sql` 或 `02-schema-with-demo.sql`；
3. 在 `application-dev.yaml` 配置 `url/username/password`；
4. 用 `@MapperScan` 扫描 Mapper。

本项目：

- `application.yaml` 读取环境变量，默认 `localhost:3306/MyPetStore`、`root` 空密码；本机验证时通过 `DB_PORT=3307` 指向便携 MySQL。
- `spring.sql.init.mode=never`：应用启动不自动建库/清库，避免误删演示数据。
- 两个工程各自 `application-dev.yaml` 只放开发默认值，不提交真实密码。
- `MyPetStore-SSM/src/main/resources/database/` 是根目录 SQL 的只读副本，方便在 IDE 内查看；维护仍以根目录为准。
- `@MapperScan("org.csu.mypetstore.mapper")` / `org.csu.mypetstore.admin.mapper`。

## 4. Spring MVC 验证

视频中的演示接口：

```java
@GetMapping(value = "/demo", produces = "text/plain;charset=UTF-8")
@ResponseBody
public String demo() { return "Spring MVC 初始化成功！"; }
```

本项目实现为 `DemoController`（`@RestController`，`@Profile("dev")`）：

- `GET /demo` → `text/plain;charset=UTF-8`，正文“Spring MVC 初始化成功！”；
- `GET /demo/user?username=alice` → JSON 只读用户视图（id/username/displayName/role/status），不包含密码；
- 不存在用户 → 404；
- 仅在 `dev` profile 注册，正式 profile 不会暴露演示接口。

运行验证：

```powershell
curl.exe http://127.0.0.1:8080/demo
curl.exe "http://127.0.0.1:8080/demo/user?username=alice"
```

## 5. 用户查询链路

视频中的链路是 `UserMapper → UserService → UserDemoController`。本项目：

- `StoreUserMapper#selectByUsername`（注解 SQL）；
- 正式登录：`AuthService#loginUser` 校验角色/状态/BCrypt；
- 个人资料：`ProfileService#get/update`；
- 演示接口：`DemoController#user` 直接调用 Mapper，只用 `UserReadResult` 暴露展示字段。

为什么没有单独建 `UserDemoController`：正式业务已经由 `AuthController`/`ProfileController` 覆盖；为避免两套重复代码，把“验证查询链路”的只读接口收敛到 `DemoController`，生产业务仍走 Service。

## 7. Thymeleaf 验证

视频用 `Model` + `templates/demo/user.html` 验证“Model → 模板 → HTML”。本项目把同一机制用于真实页面：

| 页面 | 模型 | 模板 |
| --- | --- | --- |
| 首页 | `home`（分类、新品、精选） | `Main.html` |
| 分类 | `search`、`pageResult`、`pageLinks` | `Category.html` |
| 详情 | `detail`、`product`、`images` | `Product.html` |
| 购物车 | `cart` | `Cart.html` |
| 结算 | `confirm`、`form` | `Checkout.html` |
| 订单 | `pageResult`、`status`、`orderNo` | `ListOrders.html` |
| 订单详情 | `detail`、`order`、`items` | `ViewOrder.html` |
| 支付 | `order` | `Payment.html` |

模板使用 `th:text`（默认转义）、`th:each`、`th:if`、`th:field`、`th:action`；金额 `@money.format(...)`，时间 `@fmt.dt(...)`；所有 POST 表单带 `_csrf`。

## 9. 与视频的差异

| 视频 | 本项目 | 原因 |
| --- | --- | --- |
| JDK 27 | JDK 17 源码级别，Boot 4.1.2 | 本机 JDK 17；PRD 未强制 27，Boot 4 支持 17+ |
| Qoder CN AI IDE | IntelliJ IDEA / Maven 命令行 | 工具不影响工程结构与验收 |
| `MyPetStore-SSM-demo` 单工程 | 用户端 + 管理端两个工程 | PRD 要求独立端口/Cookie/角色 |
| Gitee 推送 | GitHub `zhanchongen/MyPetStore` | 用户指定仓库 |
| 演示接口直接返回实体 | `UserReadResult` 只读视图 | 避免密码散列泄露 |
