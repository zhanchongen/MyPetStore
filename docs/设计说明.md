# 设计说明

本文说明 MyPetStore 实验一两个工程的结构、关键流程、数据与安全设计。需求基线是 `MyPetStore-PRD.pdf` V1.1；当实验指导书、参考 UI 与 PRD 冲突时，以 PRD 为准。

## 1. 目标与范围

实现一个服务器端渲染的宠物商城，分为两个**独立构建、独立运行**的 Spring Boot 应用：

| 应用 | 目录 | 端口 | 会话 Cookie | 使用者 |
| --- | --- | --- | --- | --- |
| 用户端 | `MyPetStore-SSM` | 8080 | `PETSTORE_USER_SESSION` | 游客、CUSTOMER |
| 管理端 | `MyPetStore-admin` | 8081 | `PETSTORE_ADMIN_SESSION` | ADMIN |

两端连接同一个 MySQL 8 数据库 `MyPetStore`，共享七张业务表；购买、补货、发货等业务不通过 HTTP 互调，而是共同读写数据库。

**P0 已实现**：游客浏览、两级分类、名称搜索、分页、商品详情；登录/退出、角色与状态校验、双端独立会话；持久购物车（合并、数量 1—99、最多 20 种、失效条目）；整车结算确认、原子下单、本人五状态订单、订单号精确搜索、取消恢复库存；显式模拟支付成功/失败/重复/并发；管理端登录、分类维护、商品维护与上下架、增量补货、全站订单、发货。

**选定 P1**：个人资料、修改密码、确认收货、管理端用户启停。

**明确不做**：注册、验证码、记住登录、第三方登录、地址簿、优惠券、运费/税、真实支付与退款、图片上传、商品删除、订单任意编辑、管理端重置密码、相册维护、自动关单、物流轨迹、推荐/销量、REST API、移动端。

```text
.

├─ scripts/                      # 可重复执行的 smoke 脚本
├─ MyPetStore-SSM/               # 用户端（Spring Boot + Thymeleaf）
│  ├─ src/main/java/org/csu/mypetstore/
│  │  ├─ config/        # MyBatis-Plus 分页、拦截器注册、BCrypt
│  │  ├─ common/        # 金额/时间格式、分页参数、页码链接、密码策略、订单号
│  │  ├─ domain/enums/  # 角色、状态、订单状态、商品类型/排序
│  │  ├─ entity/        # 七张表对应实体
│  │  ├─ mapper/        # MyBatis-Plus Mapper + XML
│  │  ├─ dto/           # 页面只读模型与表单
│  │  ├─ security/      # SessionUser、CsrfFilter、AuthInterceptor
│  │  ├─ service/       # 业务与事务

│  │  └─ MyPetStoreSsmApplication.java
│  ├─ src/main/resources/
│  │  ├─ templates/     # Thymeleaf 页面
│  │  ├─ static/        # CSS、JS、站内商品图
│  │  ├─ mapper/        # Product/Cart/Order 的 XML
│  │  └─ database/      # 根目录 SQL 的只读副本
│  └─ src/test/java/    # 单元与 MockMvc 测试
└─ MyPetStore-admin/     # 管理端（独立 Spring Boot）
   └─ 包 org.csu.mypetstore.admin
      ├─ config/ entity/ mapper/ form/ dto/
      ├─ security/     # AdminAuthInterceptor、CsrfFilter、SessionUser
      ├─ service/      # 登录、分类、商品、订单、用户
```

两端不共享 Java 模块，避免为一个课程项目引入多模块构建复杂度；需要复用的分页、格式化、CSRF 等代码在各自工程内保持同构。

## 3. 分层与请求链

用户端典型请求：

```text
浏览器
  → CsrfFilter（静态资源跳过；写请求校验会话 Token）
  → AuthInterceptor（仅 /cart/**、/checkout/**、/orders/**、/payment/**、/profile/**）
      从 Session 取 SessionUser，再按 id 查 store_user，校验 CUSTOMER + ENABLED
  → Controller（参数绑定、分页参数、模型属性）
  → Service（业务校验、事务、锁、状态机）
  → Mapper（MyBatis-Plus BaseMapper / 注解 SQL / XML）
  → MySQL
  → Thymeleaf 模板（服务端渲染）
```

- 页面模型以 Java `record`（分页、搜索结果、结算确认、订单详情）和 Lombok 实体为主；模板调用 record 的访问器方法（如 `pageResult.records()`）。
- 金额统一由 `MoneyFormatter` 输出 `¥` + 两位小数；时间由 `DateTimeFormatterBean` 输出 `yyyy-MM-dd HH:mm:ss`，避免模板各自格式化。
- 所有写操作使用 POST；成功后 redirect，失败时回显页面并用 flash 消息提示，避免刷新重复提交。
- 全局模型 `GlobalModelAdvice` 提供 `currentUser`、`cartCount`、`_csrf`；错误统一进入 `error/400|403|404|409|500`。

管理端请求链：

```text
CsrfFilter → AdminAuthInterceptor（除 /login、静态资源、/error 外全部拦截）
  → 按 Session 中管理员 id 重查 store_user，要求 ADMIN + ENABLED
  → Controller → Service → Mapper → Thymeleaf
```

管理端拦截器每次请求重查数据库，因此管理员被禁用或角色变化后，现有会话立即失效，而不是等 Cookie 过期。

## 4. 数据模型

| 表 | 作用 | 关键约束/说明 |
| --- | --- | --- |
| `store_user` | 用户/管理员 | `username` 唯一；`role` CUSTOMER/ADMIN；`status` ENABLED/DISABLED；BCrypt 散列 |
| `category` | 两级分类 | 一级 `parent_id IS NULL`；二级必须指向一级；`code` 唯一；同一父下 `name` 唯一 |
| `product` | 商品 | `sku` 唯一；必须归属二级分类；`price DECIMAL(12,2)`；`stock` 非负；`status` DRAFT/ON_SALE；`version` 乐观锁 |
| `product_image` | 商品相册 | 站内相对路径；一商品多图；列表/详情只读 |
| `cart_item` | 持久购物车 | 用户 + 商品唯一；数量 1—99；`version` 防旧表单覆盖 |
| `sales_order` | 订单主表 | 订单号唯一；五状态；收货快照；MOCK 支付信息；时间戳 |
| `sales_order_item` | 订单明细 | SKU/名称/封面/单价/数量/行金额快照；历史订单不随商品修改 |

演示数据由 `02-schema-with-demo.sql` 写入：4 个账号、15 个分类、60 个商品（54 上架、6 下架、3 个上架售罄）、100 条相册、10 条购物车、10 张订单（五状态各 2）、20 条明细。图片使用参考 UI 的 40 张照片和 40 张生成的 SVG 教学示意图，全部为站内路径，不依赖外网。

## 5. 关键流程

### 5.1 浏览、分类与搜索

- 首页：一级分类入口、新品（上架商品按创建时间倒序，最多 3）、精选（按人工排序，最多 4），不下架商品。
- 分类页：左侧一级分类；选中一级后显示其二级分类；支持全部/宠物/用品类型、四种排序、名称关键词、分页。分类与关键词条件在翻页链接中保留。
- 搜索使用 `LOCATE(#{keyword}, name)` 做包含匹配，避免用户输入 `%`/`_` 被当作通配符。
- 商品详情：只展示上架商品；展示分类路径、SKU、价格、库存、相册；零库存显示售罄；不存在/下架统一 404，不把技术异常伪装成业务提示。

### 5.2 登录、会话与权限

- 用户登录只接受 `CUSTOMER + ENABLED`，管理员登录只接受 `ADMIN + ENABLED`；失败统一提示“账号或密码错误，或账号不可用。”，不泄露账号是否存在。
- 登录成功后调用 `changeSessionId()` 防会话固定；Session 存 `SessionUser(id, username, displayName, role)`，不存密码散列。
- 每次受保护请求由拦截器重查 DB，处理“登录后被禁用”和“角色被修改”。
- 退出使用 POST + CSRF；用户端和管理端 Cookie 名不同，互不影响。
- 登录回跳只允许站内相对路径；拒绝 `//`、反斜杠、换行和登录/退出路径，防开放重定向。

### 5.3 购物车

- 加入：同商品合并数量；数量必须是 1—99 的整数；超过 20 种拒绝；不预占库存、不保存价格。
- 修改/移除：同时携带 `itemId` 与 `version`；SQL 条件更新 `WHERE id AND user_id AND version`，旧页面不能覆盖新数量；跨用户操作按“不存在”处理。
- 购物车行联表读取商品当前名称、封面、价格、库存、状态；商品下架/售罄/库存不足时保留行并标记失效，禁止整车结算，可单独移除。
- 购物车是数据库持久状态，退出、重启、换浏览器后仍保留；另一个账号不能读写。

### 5.4 结算与下单

1. `GET /checkout`：重新读取有效购物车，计算总数量与总额，生成 `CheckoutConfirm` 放入 Session（键 `CHECKOUT_CONFIRM`，30 分钟有效），预填用户显示名/电话。
2. `POST /checkout/submit`：校验收货人、电话、地址；重新比对购物车条目、数量、版本与商品价格/状态。购物车或价格变化返回 409，要求重新确认，不静默下单。
3. 下单事务（`OrderService.placeOrder`）按固定顺序加锁，避免死锁：
   - 锁用户（`store_user.id FOR UPDATE`）；
   - 锁该用户购物车行（按 item id）；
   - 按商品 id 升序锁商品行；
   - 校验库存、状态、价格；写订单主表与明细（快照）；扣库存并递增 `version`；删除本次结算的购物车行。
   - 任何一步失败整体回滚，不留下订单、明细、部分扣库存或半清购物车。
4. 金额只由后端按数据库价格计算，忽略表单中伪造的价格字段。

### 5.5 订单、支付、取消、确认收货

订单状态机：

```text
PENDING_PAYMENT ──支付成功──> PAID ──发货──> SHIPPED ──确认收货──> COMPLETED
       │                       
       └──取消（恢复库存）──> CANCELLED
```

- 我的订单只查当前用户；支持五状态筛选、订单号完整精确匹配、分页；订单号去首尾空白，空结果展示空状态。
- 详情展示订单号、状态、创建/支付/发货/完成时间、收货快照、商品快照、金额、MOCK 支付凭证；不展示真实物流。
- 模拟支付成功：条件更新 `WHERE id AND user_id AND status='PENDING_PAYMENT'`，写 `payment_method='MOCK'`、支付凭证、`paid_at`；重复支付保留首次凭证，不重复扣库存。
- 模拟支付失败：只记录失败提示，不改订单状态、不生成凭证；可重试或取消。
- 取消：仅本人 `PENDING_PAYMENT` 可取消；锁订单后恢复每个商品库存并递增版本，再置 `CANCELLED`；重复取消/并发支付由条件更新保证只有一种迁移成功。
- 确认收货：仅本人 `SHIPPED` 可确认，条件更新为 `COMPLETED` 并保存首次完成时间。
- 历史订单使用快照，商品后续改名/改价/下架/售罄不影响已下单明细；有效待支付订单仍可按快照金额支付。

### 5.6 管理端

- 分类：列表展示层级、编码、父分类、排序、子分类/商品引用数；新增一级或二级；编辑只允许名称与排序（编码、父子关系不可变）；删除前检查子分类和任意商品引用（含下架），有引用则拒绝。
- 商品：按一级/二级分类、名称、状态分页；列表不提供销量和删除。创建时 SKU 唯一且创建后不可改，必须归属二级分类，价格 > 0 且最多两位小数，初始库存非负，默认 DRAFT；编辑不改库存，保存时校验 `version`，冲突提示刷新；上下架是显式动作。
- 补货：独立表单，只在数据库当前库存上做 `stock = stock + ?` 并递增 `version`，不接收“目标库存”；非法数量/商品不存在/溢出拒绝且不改数据。
- 订单：全站订单按订单号精确搜索 + 五状态 + 分页，按创建时间/id 倒序；详情只读；仅 PAID 可发货，条件更新为 SHIPPED 并保存首次发货时间；重复发货提示已处理。
- 用户（P1）：只列 CUSTOMER，按用户名包含 + 状态筛选；启停限定 CUSTOMER，管理员不可互相禁用；禁用后用户端下一次受保护请求立即拒绝。

## 6. 安全设计

| 风险 | 措施 |
| --- | --- |
| 会话固定 | 登录成功 `changeSessionId()` |
| 越权访问订单/购物车/支付 | 所有查询与更新都带 `user_id`；跨用户按不存在处理，不泄露详情 |
| 禁用/角色变化后旧会话 | 每次受保护请求重查 `store_user`，校验 CUSTOMER/ADMIN + ENABLED |
| CSRF | 会话级随机 Token；所有写请求 POST；`CsrfFilter` 常量时间比较；失败 403 |
| 开放重定向 | 登录 `returnUrl` 只允许站内相对路径，拒绝 `//`、反斜杠、换行、登录/退出路径 |
| 密码泄露 | BCrypt 散列；页面/JSON/日志不输出密码；修改密码要求旧密码；密码 8—32 字符、≤72 UTF-8 字节、至少两类、无空白 |
| SQL 注入 | MyBatis `#{}` 参数绑定；排序字段走白名单枚举，不拼用户输入 |
| XSS | Thymeleaf `th:text` 默认转义；商品描述/收货地址按纯文本显示，不 `th:utext` |
| 价格/库存篡改 | 金额由后端按 DB 价格计算；库存由条件更新/行锁保证；表单不接收可信价格 |
| 旧表单覆盖 | 购物车/商品使用 `version` 条件更新；结算确认绑定当次购物车版本与价格 |
| 并发重复成交/发货 | 订单状态条件 UPDATE；支付、取消、发货只有一种迁移成功 |
| 敏感配置 | 数据库连接只从环境变量读取，仓库不提交真实密码 |

注意：自定义 Session 鉴权不是完整 Spring Security 过滤器链；本课程项目只需要登录、角色/状态校验与 CSRF，故不引入完整安全框架，减少学习噪声。生产系统应使用成熟的安全框架、HTTPS、密钥管理和审计日志。

## 7. 分页、错误与可访问性

- 分页参数：页码缺省 1，小于 1 归一；页大小默认商品 6、订单 10，允许 1—50；非整数 400；页码超出范围显示空页而不是 500。
- 页码链接保留分类、类型、排序、关键词、订单状态、订单号等筛选条件。
- 统一错误页：400 参数错误、403 CSRF/权限、404 不存在、409 版本/状态冲突、500 未预期异常；错误页不输出堆栈和 SQL。
- 所有表单有 label；图片有 `alt`；登录/支付/订单状态不只靠颜色表达；管理端侧栏与表格有明确文字。

## 8. 指导书与 PRD 差异说明

| 主题 | 指导书/原型 | 本项目（PRD 优先） |
| --- | --- | --- |
| 注册/验证码/第三方登录 | 原型含微信、注册、验证码 | 不实现；只有账号密码登录 |
| 管理端改密/删单 | 指导书含管理员改密、删除订单 | 不实现；订单只读，发货是唯一状态操作 |
| 商品 Item 独立表 | 指导书传统 PetStore 有 item 表 | 单 SKU 商品，不引入 item 表 |
| 立即购买/推荐/销量 | 原型有立即购买、推荐、销量 | 删除；加入购物车后整车结算 |
| 运费/优惠/优惠券/地址簿 | 原型有 | 删除；结算只填本次收货信息 |
| 图片上传/商品删除 | 指导书可能含 | 不实现；封面为站内路径，商品只上下架 |
| 验证码/记住登录/忘记密码 | 原型有 | 删除；登录失败统一提示 |
| 相册维护 | 指导书可能含 | 本期不做；相册只读展示 |

## 9. 已知限制

- 模拟支付没有真实支付网关、退款、对账；支付凭证仅用于状态机演示。
- 没有自动关单、物流公司/运单号、售后、优惠计算、库存预占。
- 没有集成测试自动化；跨工程并发、故障注入等场景以代码审查和手工验证为主，见 `docs/验证记录.md` 的“覆盖边界”。
- 管理端不提供相册维护、角色提升、管理员互禁、密码重置。
- 商品图片为课程参考 UI 与生成的 SVG 教学示意图，不代表真实商品。
